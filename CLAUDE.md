# Knight Music — native iOS/iPadOS Navidrome client

A native SwiftUI music player for a personal Navidrome server (OpenSubsonic API). The look matches
**Arpeggi / Apple Music on iOS 26**: real Apple **Liquid Glass**, dark, red accent. Screens to match are in
`ref/` (Arpeggi on iPad). **Everything ships working against the real server — no mockups, no fake data,
no placeholder screens, no "coming soon".** If a feature is in scope, it works end to end.

## Hard constraints
- **No Mac.** We're on Linux. GitHub Actions (`.github/workflows/ios.yml`, macos-26 runner) is the compiler.
  You cannot run Xcode, Swift or a simulator locally. Write code carefully and verify through CI (below).
- Minimum **iOS/iPadOS 26.0**, iPhone + iPad (`TARGETED_DEVICE_FAMILY 1,2`). Swift 5 language mode, Xcode 26 SDK.
- Project file is generated by **XcodeGen** from `project.yml`. Never commit `*.xcodeproj`. Any new folder
  under `KnightMusic/` is picked up automatically. Dependencies (SPM): **GRDB 7**, **Nuke 12 / NukeUI**. Do not
  add others without a strong reason.
- Distributed as an unsigned IPA installed with SideStore (free Apple ID): **no** iCloud/CloudKit, App Groups,
  push, or other paid-account entitlements.

## Verify every change through CI (mandatory)
1. Commit on your branch, `git push -u origin HEAD`.
2. `gh run watch $(gh run list --branch "$(git branch --show-current)" --limit 1 --json databaseId -q '.[0].databaseId') --exit-status`
   (wait ~1 min after push for the run to appear). On failure: `gh run view <id> --log-failed | grep -E "error:" | head -60`.
3. Fix and repeat until **BUILD OK**. Never hand back code that hasn't compiled in CI.
4. UI work: include `[shots]` in the commit message → artifact `screens` with iPhone + iPad PNGs of every
   screen (demo server). `gh run download <id> -n screens -D /tmp/<yourbranch>-screens` and **look at them**
   with the Read tool. Compare with `ref/*.PNG`. Iterate until it looks right.

## Architecture
```
KnightMusic/
  App/          KnightMusicApp, AppModel (root @Observable, owns everything), DebugLaunch (screenshot mode)
  Core/API      Models, SubsonicClient (actor), ServerAccount, AccountStore, Keychain, AddressResolver
  Core/Library  LibraryDatabase (GRDB pool + migrations + FTS5), SyncEngine, LibraryRepository (live queries)
  Core/Playback PlayerEngine, PlayQueue, NowPlayingCenter, RemoteCommands, Scrobbler, StreamCache, SleepTimer
                PlayerEngine+AutoMix: second deck, host-time-synced start, handoff, tail
  Core/AutoMix  AutoMixPlan, AutoMixClient (plans from server/automix), MixTap (MTAudioProcessingTap gain/filters)
  Core/Downloads DownloadManager (background URLSession), StorageManager
  Core/Artwork  ArtworkLoader (Nuke), AnimatedArtworkService (m8tec + animated WebP), ArtworkPalette
  Core/Support  Log (os.Logger subsystem com.knightabdo.knightmusic), NetworkMonitor, Haptics, AppSettings
  UI/DesignSystem  tokens + reusable components (ArtworkView, AnimatedArtworkView, rows, carousels, A–Z index…)
  UI/Shell      RootView: TabView(.sidebarAdaptable) + mini player accessory + full player presentation
  UI/Home UI/Search UI/Library UI/Detail UI/Player UI/Settings UI/Onboarding
```
- **Offline-first.** Every list/screen reads the local GRDB mirror (instant, works offline). The network only
  feeds the mirror (SyncEngine) or performs actions (star, rate, playlist edits → write to server, then to DB
  optimistically). UI never awaits the network to show something already known.
- **Observation.** `@Observable` classes, `@MainActor` for anything UI-facing. Root `AppModel` is injected
  with `.environment(appModel)`; its children (`player`, `library`, `downloads`, `artwork`, `settings`) are
  also injected individually so views can `@Environment(PlayerEngine.self) var player`.
- **Accounts.** `ServerAccount` (name, username, ordered `addresses: [URL]`) persisted as JSON; password in
  Keychain. `AddressResolver` picks the first reachable address (LAN first, then Tailscale), re-checks on
  network changes. Multiple servers supported; one active.
- **Auth.** Subsonic token auth: `t = md5(password + salt)`, `s = salt`, `u`, `v=1.16.1`, `c=KnightMusic`, `f=json`.
- **Cross-module contracts** (keep these names/signatures stable):
  - `SubsonicClient` (actor) — nonisolated URL builders:
    `streamURL(songId:maxBitRate:format:timeOffset:) -> URL`, `downloadURL(songId:) -> URL`,
    `coverArtURL(id:size:) -> URL`; async API methods throw `SubsonicError`.
  - `AppModel.client: SubsonicClient?` — the client for the active account/address (nil when logged out).
  - `DownloadManager.localFileURL(for songId: String) -> URL?` (downloaded file, or nil)
  - `StreamCache.cachedFileURL(for songId: String) -> URL?`
  - `ArtworkLoader.image(coverArt: String?, size: Int) async -> UIImage?`
  - `AnimatedArtworkService.animatedArtwork(for song: Song) async -> AnimatedArtwork?` and
    `nowPlayingEntries(for song: Song) async -> [String: Any]` (MPNowPlayingInfo keys for lock screen).
  - `PlayerEngine.play(_ songs: [Song], startAt: Int, shuffle: Bool)`, `togglePlayPause()`, `next()`,
    `previous()`, `seek(to:)`, `enqueue(_:next:)`, `currentSong`, `isPlaying`, `currentTime`, `duration`,
    `queue`, `repeatMode`, `shuffleEnabled`, `source: AudioSource`.

## AutoMix (server/automix)
Beat-matched transitions are planned on the Navidrome host by `server/automix` (Python service `knight-automix`,
see its README) and executed by the app. Tune mixing in `planner.py` (deploy with `deploy/install.sh`, no app
release needed); bump `PLAN_VERSION` and `AutoMixPlan.supportedVersion` together only when the plan format changes.

## Liquid Glass — use Apple's real APIs only (iOS 26 SDK)
Never fake glass with `.ultraThinMaterial` + borders + blur stacks. Never draw custom frosted panels.
- Navigation: `TabView` with `Tab(...)` values and `.tabViewStyle(.sidebarAdaptable)` (iPad sidebar like
  `ref/IMG_1160.PNG`, iPhone floating glass tab bar). Search tab: `Tab(role: .search)`.
  `.tabBarMinimizeBehavior(.onScrollDown)`. Library sections live in `TabSection("Library")`.
- Mini player: `.tabViewBottomAccessory { MiniPlayer() }`; read `@Environment(\.tabViewBottomAccessoryPlacement)`
  to adapt when collapsed (`.inline`) vs expanded.
- Full player: `.fullScreenCover`/sheet with `.navigationTransition(.zoom(sourceID:in:))` from the mini player's
  artwork (`.matchedTransitionSource(id:in:)`).
- Custom floating controls: `.glassEffect(.regular.interactive(), in: .capsule)` / `.circle`; group adjacent
  glass in `GlassEffectContainer(spacing:)`; morph between states with `.glassEffectID(_:in:)`.
  Tinted primary: `.glassEffect(.regular.tint(.accentColor).interactive())`.
- Buttons: `.buttonStyle(.glass)` and `.buttonStyle(.glassProminent)`. Toolbars, navigation bars, search fields,
  sheets, menus and context menus get glass automatically — don't restyle them.
- Hero artwork under glass: `.backgroundExtensionEffect()`. Scroll edges: `.scrollEdgeEffectStyle(.soft, for: .top)`.
- Glass goes on the **navigation/control layer only**, never on content (rows, cards, artwork).

## Visual spec (match `ref/`)
- Dark only (`UIUserInterfaceStyle Dark`). Background pure black. Accent **Arpeggi red** `#FA2D48`
  (asset `AccentColor`), user-changeable later in Settings → Customize.
- Large navigation titles (34pt bold). Section headers: 22pt bold + chevron ("Recently Played ›").
- Album tiles: square artwork, 8pt corner radius, title 15pt regular white, subtitle 13pt secondary, one line each.
  Grids adapt: 2 cols iPhone portrait, 5 on iPad landscape (≈ 160–200pt tiles).
- Artist rows: circular 56pt image, name 17pt, chevron, inset separators, A–Z index on the trailing edge (red).
- Grouped settings: inset rounded sections (`.insetGrouped`), red action rows ("Force Quick Scan", "Log Out").
- Full player (`ref` player shot): artwork large and centered with soft shadow; title 20pt semibold, artist 17pt
  secondary; heart · 5-star rating · ••• row; scrubber with elapsed / "Streaming • MP3 • 249 kbps" / remaining;
  shuffle · previous · play/pause · next · repeat; bottom row: AirPlay · settings · dismiss chevron · lyrics ·
  queue · sleep timer. Background = blurred/gradient palette from artwork (animated artwork plays full-bleed
  when available — tall 3:4 variant on iPhone portrait).
- Motion: spring animations (`.smooth`, `.snappy`), haptics on play/pause/star, artwork crossfades, no jank:
  downsampled images, lazy stacks, stable ids.

## Animated artwork
- `GET https://artwork.m8tec.top/api/v1/artwork/search?artist=<artist>&album=<album>` →
  `{ "url": <square master .m3u8>, "url_tall": <3:4 master .m3u8>, ... }` (404/empty when none).
  Clean the album name (strip "(Deluxe)", "[…]", "- Single"), first artist only.
- Master playlists list H.264 (`avc1`) and HEVC variants. Each variant playlist references **one fragmented MP4
  file via byte ranges** — download that single `.mp4` (no HLS needed) for the chosen variant (H.264 ≈1080px)
  and cache it on disk keyed by albumId. Cache the lookup result (incl. "none") in the DB to avoid re-querying.
- Fallback: Navidrome `getCoverArt` for albums with an animated `cover.webp` (detect animated WebP/GIF frames)
  → convert to a looping H.264 MP4 on device (AVAssetWriter) and cache.
- In-app: `AnimatedArtworkView` = `AVPlayerLayer` + `AVPlayerLooper`, muted, never steals audio session.
- Lock screen / Now Playing: iOS 26 `MPMediaItemAnimatedArtwork` with
  `MPNowPlayingInfoProperty1x1AnimatedArtwork` (square) and `MPNowPlayingInfoProperty3x4AnimatedArtwork`
  (tall) — handlers return the cached local MP4 file URL and a preview UIImage.

## Code style
- Small focused files; one primary type per file. Names over comments; comment only non-obvious "why".
- `async/await` everywhere; no Combine unless GRDB requires it. No force unwraps on network data.
- Errors surface to the user (banner/toast) and to `Log`; never silently swallowed.
- No placeholder/sample data in production code. `#Preview` blocks are optional and must not ship fake data
  paths into the app.
